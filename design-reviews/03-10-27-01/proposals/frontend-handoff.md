## Component and responsive contract

**Tab strip:** navigation only, 44 units high, roughly 140–220 per tab. One tab retains the strip; zero tabs uses the existing empty/Open state. Many tabs scroll at readable minimum widths, with fixed **Documents (count)** listing every filename, distinguishing path, active/Unsaved/conflict/unavailable status and separately labeled Close. Reveal the active tab without reordering. Arrow/Home/End and existing reorder conventions remain; ⌘W closes through existing loss guards. Closing the last tab opens the empty state, not Quit.

Active = solid surface, semibold filename, 2-unit underline; focus = separate 2-unit ring; modified = reserved dot plus accessible/textual Unsaved. Keep Close reachable without hover and ≥24×24. Middle-truncate long names with extension/distinguishing suffix; duplicate basenames add differing parent, allowing a 52-unit strip without multiple rows. Full identity/status is reachable through Documents and Show path. Long file-error text belongs in the document header/list, not squeezed tabs. Tree current-file marking never forces expansion/scroll on ordinary tab changes.

**Layout:** native titlebar remains system-managed. Proposed logical units, not inferred screenshot scale: sidebar reference 260 (retain user's saved width); document header about 74 plus 24 state row; 32–64 reading inset reducing to 16–24. Preserve saved prose measure (760 in mockups), font/size/line height. Tables/code/images can exceed prose measure through intentional local overflow.

**Narrow/enlarged text:** move Outline/Reading settings into labeled Document… before shrinking Edit/Save/Return. Collapse sidebar/outline to dismissible panels if reader would fall below ~480 available units; restore user choices as space returns. At 640×480, keep Sidebar, active tab, Documents, Back/Forward, filename, Edit or Save/Return and Document… reachable. Use the separate action row in revised [reading](mockups/07-narrow-workspace.svg) and [editing](mockups/14-narrow-editing.svg), with metadata/status wrapping below; do not force the wide one-row header into this width. Header groups wrap with 200% text/long ES labels; metadata yields before actions. Search uses a dismissible 280–340 panel. Menus/panels scroll within the viewport; no whole-window horizontal scrolling. Native minimum size does not demonstrate zoom/reflow accessibility.

## Decisions for design review and frontend investigation

- Recommend one rich **section** at a time to preserve current save/recovery scope. A whole-document model would require a separate scope decision.
- Resolve lossless round-trip coverage and opaque-node/read-only boundaries; no normalization or discarded syntax by default. [Detailed byte-preservation risks and technical questions](interaction-spec.md#markdown-round-trip-gate-and-technical-questions).
- Verify rich history/caret/checkpoint restoration and heading-boundary remapping. Cross-save Undo is not promised under the current session-ending Save model.
- Selected-subfolder search is a proposed extension: the current API has no subtree parameter. Keep root search available; disable the narrower action with a reason until support is verified. No editor library or architecture is selected here.

## Testable acceptance criteria (all NOT TESTED in the app)

1. With 1, 5 and 29 tabs, active tab is visibly revealed; Open/Settings never share the tab lane. Duplicate names, long EN/ES names and modified tabs retain identity, Close and Documents routes.
2. At 640×480, larger supported widths and 200% text, essential actions remain readable/reachable; intentional table/code overflow never becomes whole-window overflow. Narrow Sidebar/Search overlays dismiss and return focus.
3. File/menu/Projects-dropdown routes invoke the same Open commands and preserve limited file grants, root replacement guards, saved preferences and tab order.
4. Reload-current shows a checkmark plus neutral target-named message, announces once and expires without moving any tree row. Last verified status remains accessible; errors/uncertainty/conflicts do not expire as success.
5. Root, folder, file, tab, paragraph, selection and table menus expose only relevant grouped actions and honest disabled reasons.
6. Every menu dismisses on outside click, Escape, action, new menu, relevant scrolling, tab switch, target invalidation and blur. Cancellation preserves selection; focus returns by cause; no stale floating control remains.
7. Reading click/double-click/typing/checkbox operation cannot write content. Labeled Edit and contextual/keyboard routes target the correct native section and create a clean session.
8. Editing uses the same rendered heading/paragraph/list/link/image/table/code blocks and scroll surface; no raw Markdown pane, source/preview switch or split is introduced. Section boundaries and read-only opaque nodes are named.
9. Caret placement, selection, macOS keyboard navigation, list/table/code traversal and composition work without escaping section scope or accidental document navigation.
10. Each structural/formatting/paste transaction has predictable Undo/Redo; tab/theme/checkpoint transitions preserve session history and caret. Post-restart limitations are explicit.
11. Selection formatting is keyboard reachable, preserves the range, does not hide essential text and disappears when its target/selection changes.
12. Dirty and recovery states refer to the correct revisions. Recovery saved does not clear Unsaved; Save submits once, protects submitted input, returns to reading only after success, and keeps errors/drafts safe.
13. Dirty Return/Close/folder change/Quit invoke existing loss guards; Cancel restores selection. Tab switch alone retains edits. Save a copy leaves original dirty and no unsupported destination-path claim appears.
14. Disk conflict blocks original Save, preserves draft and current comparison/safe-choice behavior. Confirmed discard/reload never silently overwrites a newer disk version.
15. Unchanged rich entry/exit has zero source-byte diff. A localized edit preserves untouched bytes, encoding/BOM/EOL and unsupported constructs. Unsafe round-trip combinations disable editing with a reason instead of changing source silently.
16. Entry, typing, save/exit, refresh and asynchronous image/font/diagram layout preserve the current reading anchor, or announce a truthful nearest-anchor fallback.
17. Search opened from Projects/tree menus or ⇧⌘F visibly names root scope and Names/Contents/Both. Outside-root explicit files are not included. Subfolder search is enabled only when a verified scoped operation exists.
18. Search supports idle/scanning/complete/stopped/partial/zero/error states, real counts/exclusions, cancellation and rejection of stale jobs; changed hits locate current text or explain fallback.
19. Clear cancels and empties without closing; Return/Escape restores tree expansion/scroll/focus and retains query/verified hits. Opening a result retains the chosen document on return to Explorer.
20. Existing image-viewing controls, file safety, no-fetch rules, local storage disclosures and confirmed cleanup scopes survive the redesigned shared shell. Actual packaged macOS behavior is verified separately from static mockups.

21. Every Settings entry raises the same separate window; closing it keeps workspace tabs and drafts intact and restores appropriate focus. Reading shortcuts target its Reading group.
22. Settings contains language, supported font/size/spacing/width controls, System/Light/Dark and the sole Documents and images only checkbox. There is no explorer duplicate.
23. Preference changes/Reset reading preserve file bytes, caret/history/scroll and unrelated values. File visibility preserves folders, tabs and grants; it does not change search scope or unsupported-file behavior.
24. Stored values restore according to their approved scopes; persistence failure is explicit and retryable. The Settings body reflows/scrolls within available work area with Done and native close reachable at narrow heights, EN/ES and enlarged text.

## Critique refinements

[Save/recovery state board](mockups/15-save-recovery-states.svg) makes clean, recovery failure, conflict and dirty exit explicit. **Save still returns to reading after acknowledgment**; the editing header exposes that result. Recovery failure does not imply original Save is unavailable; a disk conflict does. Keep draft cannot complete an exit until the current revision is acknowledged. Cancel starts focused in dirty exits. Do not remove original/draft-loss confirmations.

[Light, enlarged Spanish Settings](mockups/16-light-enlarged-settings.svg) shows stacked labels, larger controls, textual theme selection and a body that scrolls above a reachable Done action. This is an authored static composition, not a zoom test. Settings helper copy includes HTML now. Reading reset affects only Reading; visibility is separate from search coverage.

Search opens with Both selected; a checkmark supplements the selected background. The initial whole-workspace scope is static until a supported alternative exists. Search is disabled for an empty query with a visible reason. While scanning, Search becomes Stop and Clear remains available. Return submits; Return to Explorer is the separate sidebar action. Completed scans with skips say Scan finished plus actual skips; content coverage remains Markdown only until changed in a canonical specification.

Revised draft-only row/column deletion is direct and reversible through Undo, with a target-named status; no confirmation for every draft transaction. Final original-file changes still require Save. Whole-table removal or a transaction that cannot be undone needs a specific confirmation or must remain disabled. This material revision to the earlier table-menu interaction is approved design behavior.
