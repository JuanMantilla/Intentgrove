## Contextual menus

Revision 2026-10-04: **Projects** is one labeled dropdown trigger. Its arrow, root secondary click and secondary click on empty tree space open the shared Open file/Open folder/Search workspace menu. Remove standalone sidebar Open/Search buttons. Display mapped keyboard shortcuts in a right-aligned column, not embedded in action labels; do not invent bindings for unassigned actions. ⌘R hints are shown for the active file. Inactive targets require a hint only if the command routing is reconciled to that target.


Use macOS secondary click and Control-click; support existing Shift+F10/context-menu-key for focused targets and the native keyboard context route where supported. This follows [Apple's contextual-menu guidance](https://developer.apple.com/design/human-interface-guidelines/context-menus?changes=__3): actions relate to the target, and important actions also need a discoverable route. Menus shown side by side in mockups are independent examples.

Shared lifecycle: record the target and document identity at opening; secondary click does not execute anything or change documents. Place beside the click/keyboard anchor with an 8-unit gap; prefer adjacent whitespace, flip/clamp within the viewport, and avoid covering the selected text/caret when practical. Long labels wrap, menu rows start at 32 units, max height scrolls. Only one menu exists; opening another closes/replaces the prior one.

Outside pointer-down dismisses immediately and allows intended outside focus/action without unexpectedly entering editing. Escape closes and restores the invoker/caret. Action selection closes before executing and moves focus to the result; disabled actions stay disabled and explain why. Tab switch, scroll in the target surface, target invalidation, resize that invalidates positioning, or window blur dismisses; never leave a floating orphan. Do not restore focus to a removed/inactive document: tab switch focuses new navigation/document; outside click keeps the clicked focus; blur does not steal focus back. If the original target vanished, use the containing document/nearest surviving row. Menus support arrow/Home/End navigation, Return activation, visible focus and appropriate menu semantics; Tab dismisses and advances predictably. Keyboard selection/caret is restored exactly on cancellation. Any exit animation must remove hit testing/accessibility exposure immediately and honor Reduce Motion.

## Direct in-place editing

**Edit actual content: type, replace words, delete text, paste, add/remove paragraphs, modify list items and change table cells in the rendered blocks themselves. No raw Markdown text pane, separate preview, source/preview toggle, or split-screen editor is part of this design.** Code fences remain literal code because that is their document content, not a second Markdown editor. Inspecting versions after a disk conflict remains a separate read-only recovery task, never the authoring model.

Use one current **section** as the edit/save boundary, retaining existing native section descriptors and loss guards. It is not a card with its own scrollbars. The document remains one reading surface; active blocks keep typography, column, image sizes and table geometry as practical. A fine left boundary and **Editing: {actual section label}** identify scope; unaffected sections remain normally readable. Heading/preheading/whole-section labels come from valid native descriptors, not guessed DOM heading ranges.

- **Begin deliberately through Edit section:** Reading clicks, selection, double-click, typing and task-checkbox clicks never mutate content. The visible Edit section action uses the section containing the last focused reading block or viewport anchor; name the target on entry. If no reliable target exists, ask the user to select a section using named headings/“Before first heading”; do not silently choose the first. Edit section here targets the clicked block's section. Focus the equivalent block/selection, or the start of that section when no caret location exists. Entry alone produces no dirty state or file write.
- **End deliberately:** Successful Save/⌘S writes the original Markdown and returns to reading, as today. Clean Return to reading ends directly. Dirty Return, tab close, folder replacement, window close and Quit retain Save / Keep draft / Discard / Cancel guards. Keep draft waits for the acknowledged revision; Discard confirms draft/recovery loss. Switching tabs merely retains/pauses the edit. Requesting another section runs the existing pending-section guard. Escape cancels a menu/popover first; it never silently discards an edit.
- **Caret/selection:** A visible themed caret, ordinary text selection, word/line/document navigation, Shift extension and macOS Option/Command conventions. Arrows move between adjacent editable blocks within the section. ⌘A selects the active editable section and exposes that scope; ⌘←/→ moves to visual line boundaries and ⌘↑/↓ to section start/end. At a section boundary stop and announce it; offer named “Edit next section” through Document… rather than silently expanding save scope. Home/End and pointer placement respect visual lines. IME, dead keys and emoji compose atomically; formatting must not interrupt composition. Tab moves controls, except explicit list-indent/table-cell/code-indent contexts; Shift+Tab is reciprocal and a route to leave the structure always exists.
- **Undo/redo:** ⌘Z / ⇧⌘Z and Edit menu operate on rich-edit transactions, not tree/navigation. A formatting command, paste, list indent, table operation or image-property commit is one logical undo step; composition is grouped appropriately. Per-tab/session history and selection survive tab switches, theme changes and recovery checkpoints. New edits invalidate redo. Save returning to reading retains today's session-ending semantics: cross-save undo is not promised. The finish report records existing schema1 history/selection/source checkpoints and invalid-history authoring guards. Preserve that recovery contract; restart of this exact packaged UI candidate remains NOT TESTED end-to-end.

| Markdown content | In-place operation / preservation |
|---|---|
| Headings / paragraphs | Edit rendered text at its existing scale. Return splits a paragraph; heading Return starts a following paragraph. Heading level via block-format disclosure; use the native-owned section byte span and safe heading remap reported in the finish evidence; refuse transformations that cannot retain the section boundary. Preserve neighboring anchors; rendered-editor/native tests do not establish packaged acceptance. Shift+Return creates an explicit hard break; preserve existing soft breaks. |
| Ordered/unordered/task lists | Return creates a sibling; Return on an empty item exits one list level. Tab/Shift+Tab indent/outdent within valid depth. Task checkboxes mutate only in Edit. Preserve numbering style, nesting, loose/tight spacing and unchanged markers. |
| Links | Reading follows existing allowed navigation. Editing click positions/selects text, never follows the URL. Link… edits label/destination/title in a small anchored popover with Apply/Cancel. Validate the target without fetching it; preserve reference links and definitions. |
| Images | Select the existing rendered image as an object. Image… edits alt, local Markdown target and title in a popover. No resize handles or asset rewriting. Keep local grant/placeholder restrictions; existing image bytes are untouched. |
| Tables | Edit cell text in place; Tab moves cells, arrows navigate text, Escape exits cell editing before another Escape closes its menu. Last-cell Tab never silently appends data. Explicit row/column/header/alignment commands; preserve escaped pipes, inline content and alignment. Wide tables scroll locally. |
| Code blocks / inline code | Edit literal code inside the existing highlighted block, preserve language/fence/indentation, no execution. Code owns Tab indentation; Escape then Tab leaves it. Language label opens an anchored field; never a full source pane. Inline code edits literal text with clear boundary navigation. |
| Blockquotes / rules / other supported inline formatting | Block-format/More… handles quote nesting, strikethrough and rule insertion. Keep semantic structure; unsupported forms follow the preservation rule below. |
| Mermaid / YAML metadata / raw HTML / unknown extensions | Preserve as opaque original source-backed blocks until a lossless direct interaction is specified. Keep current safe rendered/escaped presentation and a lock/reason. Do not expose a raw Markdown editing fallback. If moving/splitting the block or surrounding edit cannot preserve its exact bytes and boundaries, block that operation or make the affected section read-only with a reason. |

Formatting appears only after a nonempty selection or an explicit block-menu request. A compact toolbar offers Bold, Italic, Link, Inline code, block type and More…; actions have accessible names, pressed states and keyboard equivalents in Edit → Format. Position in nearby whitespace, reposition once if necessary, dismiss on collapse/scroll/change; keyboard invocation preserves the range. No every-heading permanent edit-button repetition is required with the labeled Edit route. Markdown shorthand conversion is a proposed option only if its literal source can be preserved and one Undo restores the typed text; otherwise defer it.

**Save/status:** Dirty derives from source differences, not entering Edit. Tab dot plus textual Unsaved in edit header; clean Save disabled. Separately show “Saving recovery…,” “Recovery saved on this Mac,” or “Recovery could not be saved · Retry” only for actual acknowledgments. Recovery never means saved original. During Save, show Saving…, prevent a second submit and retain the current protection against typing a revision the closed session would lose. Failure keeps draft/selection and original safety guarantees. Save a copy retains original dirty state and picker cancellation/replacement behavior; do not invent a full destination path unsupported by the current API. Expose **Save As…** through Document… and the existing native File route, with its current **Save a copy** semantics; picker cancellation leaves the session intact and a copy does not clear the original dirty state. Conflicts block Save and retain Inspect versions / Keep my edit / Save a copy / confirmed Use disk version. Warn separately on recovery cleanup or safety-copy inventory failure after successful disk write.

**Opaque operations and explanations:** Mermaid, YAML metadata, raw HTML and unknown constructs retain their original bytes and safe rendered/escaped representation. They are not editable literal-code fields. Keep surrounding supported blocks editable only where exact opaque boundaries survive. Disabled or refused Delete, split, paste, conversion or movement explains the named construct and affected operation, for example: “Cannot split across this Mermaid block; its original Markdown is preserved. Edit the surrounding text separately.” Preserve the draft and selection after refusal; do not silently drop bytes or offer a source pane. Whole-table removal remains disabled with its own reason in the reported delivered path. Other unsupported mixed structural operations use the same specific-reason rule.

**Keyboard/accessibility handoff:** The active section is one named tab stop; avoid a tab stop for every text leaf. Keyboard/context-menu formatting retains the source selection and Escape restores the caret. Provide explicit exits from table/list/code contexts (including Escape then Tab where applicable), visible focus, pressed formatting states and named block controls. Status announces scope, refusal and actual Save/recovery acknowledgments once; surrounding sections stay in reading order. At narrow/enlarged/localized sizes, wrap controls and clamp transient tools without hiding the caret or introducing another document scroll surface. These are design requirements; physical IME, VoiceOver and final native/reflow behavior remain NOT TESTED.

**Reading continuity:** Store block/heading identity plus relative viewport offset, caret/range and document version; preserve the actual clicked passage on entry and the equivalent text on save/exit. Editing must not mount a second independently scrolling pane. Pin the block near the prior viewport position as content grows; restore nearest surviving anchor and announce fallback after deletion/reparse. Find/outline operate on current rich draft with clear session scope and do not contaminate authored headings with UI labels. Retain image/diagram/font load anchoring and per-tab reading positions.

## Markdown round-trip gate and technical questions

The saved artifact remains Markdown. An unchanged session must produce no source changes. Untouched bytes outside the native section remain exact; unchanged source-backed nodes within it must not be normalized merely by entering/saving rich editing. Explicit user changes can alter the targeted construct; do not normalize unchanged content into the original. If a safe localized serialization is unavailable, block original Save, retain the draft and explain the unsupported construct. An explicitly requested normalized copy would require a separate, clearly disclosed flow; this handoff does not authorize it. If safety cannot be guaranteed, keep the section readable and explain why editing is unavailable. Never silently drop unsupported nodes.

Editing reconciliation from the finish report (reported, not newly verified):

1. Rendered selections map to localized source transactions inside native-owned section byte spans; heading remapping, multi-leaf/paragraph edits, nested lists/quotes, literal code and cell operations are reported delivered. Unsafe structural crossings remain refused; no whole-document expansion or source fallback.
2. Preserve untouched source, BOM where applicable, trailing whitespace/newlines, soft/hard breaks, escapes/delimiters, reference links/images/definitions, fences/languages, list markers/start numbers, table pipes/alignment and opaque constructs. Do not normalize on entry or on an unchanged session. CRLF Save remains explicitly DEFERRED; non-LF authoring guards remain, rather than claiming all-EOL authoring support.
3. Existing CodeMirror EditorState/historyField JSON and schema1 checkpoints retain source/history/selection without mounting a source editor. Invalid history blocks authoring/checkpoint replacement rather than dropping history. No new dependency/schema decision is required by the reported delivered path. Exact packaged recovery/Find/caret/native-menu journeys still require acceptance.

Remaining validation and unrelated questions:

4. Can selected-subfolder search honor a subtree inside the already granted root, exclusions, streamed job identity, cancellation and stale-result guards? The current `startFolderSearch(rootId, query, mode, includeIgnored)` has no subtree parameter. No scope support is assumed or architecture chosen.
5. Can native menu command state, Control-click/keyboard context routes and rich selection clipboard behavior be shared predictably? Verify on the supported macOS/WebKit build.

The fidelity acceptance corpus must cover every applicable risk above plus malformed/unknown syntax, nested mixed structures and sections containing preserved blocks; CRLF Save remains outside the current gate under the recorded deferral. Compare source bytes, not just rendered similarity. Native save/conflict/recovery checks and frontend interaction tests remain separate.

## Folder search states

Choose the integrated field **inside the opened search surface**, rather than placing an always-active input above the tree. This keeps scope controls available without imposing a form on ordinary browsing. The user-directed revision removes the duplicate sidebar search button. Projects is the visible dropdown route; the root/blank-tree contextual menu, native Edit menu and ⇧⌘F provide additional access.

Opening Projects → Search workspace… / the project-tree menu / ⇧⌘F focuses the query; explicit scope is **Entire workspace: {root}**, including subfolders and excluding individually opened outside-root files. Matching defaults to the existing **Both** mode, with Names / Contents / Both shown as a separate choice. Screen 05 now shows Both on initial opening; screen 06 illustrates a deliberate Contents selection. Both states use a checkmark as well as a selected background. A future folder action selects **Folder: {relative path}**, including descendants, with an explicit return to entire workspace. Root/query/mode/scope changes invalidate old results, cancel the old job and reject late batches.

Return or Search starts the scan (avoid auto-running an expensive scan on every keystroke). Empty query shows “Enter a query to enable Search” and disables Search. Scanning replaces Search with Stop while keeping Clear available; it displays Scanning and the actual count, with results streaming without moving focus. Stop retains verified hits labeled **Stopped · Partial results**. Clear cancels/invalidate jobs, empties query/results and focuses the field; it does not close search. Scope/mode remain. The field's clear × and labeled Clear do the same thing. Errors preserve the query and offer Retry; zero hits says No matches plus scope/mode; partial/skipped results show true counts and reasons. Include ignored remains explicit, default off, with existing exclusions explained; no false promise to search every file.

Results group by filename, show distinguishable relative parent paths, name/content match label, line/context and highlighted matches. Multiple hits expand within their file group; counts distinguish hits from files and actual shown vs capped results. Arrow/Enter navigates/opens a verified hit into an existing/new tab; changed/moved text uses current fallback feedback. Opening a hit does not silently discard edits. Return to Explorer or Escape within search dismisses it, cancels a running job and restores tree scroll, expanded branches and prior row focus, while retaining query/mode/scope and verified results labeled stopped/partial where appropriate. Reopen does not auto-rescan. After a chosen result, keep the new active document and passage; tree restoration does not revert the document. At narrow width, search is a dismissible panel and result selection can close it to expose the document without losing search state.

## Critique clarification: transient controls and validation

Scrolling the owning document dismisses a menu; scrolling **inside a long menu** scrolls its rows and must not dismiss it. Outside pointer-down closes a menu and may perform the intended explicit outside control action once; it must not mutate content or reinterpret a reading click as Edit. Subfolder search stays disabled with an accessible reason until supported. Shift+F10/context-menu-key are availability-dependent routes; Projects, Document… and native menu actions remain the visible/keyboard alternatives.

Access and dirty-loss dialogs are modal within their owning workspace window: name/description and requested full path remain inspectable, initial focus goes to Cancel, Escape cancels, background controls are inert, and closing returns focus to the originating link/control when present. A native file picker is a second modal stage; cancelling it returns to the access dialog, rather than committing a history visit. Settings is nonmodal and uses its own close rules.

For long paths, show the authored href and resolved destination separately, wrap them and allow selection/copy; no essential identity is hover-only. See [screen 11](mockups/11-html-link-access.svg). Focus return after invalidation uses the nearest surviving logical target.

Static [save states](mockups/15-save-recovery-states.svg) specify feedback only. Validate correct revision acknowledgments, safety on failed Save, unchanged bytes, IME/caret/Undo, and dirty exits on macOS with disposable files. The [enlarged Settings composition](mockups/16-light-enlarged-settings.svg) does not verify actual 200% resizing.
