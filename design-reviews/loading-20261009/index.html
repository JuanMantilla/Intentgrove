Motion specification / proposed

Quiet by default

  • Dots: 6–7 px, 6 px gaps, 1.2 s cycle; three staggered pulses with at most 3 px vertical travel.
  • Placeholder breathing: 1.7 s opacity cycle. Use only for known UI structure, never guessed document paragraphs or an invented image composition.
  • Scans: 2 s moving line, clearly indeterminate. Counts update from actual work; no percentage without a known total.
  • Measured progress: track moves only when verified bytes or item totals change. No artificial completion or fake animation to 100%.
  • Visibility: propose a 150 ms reveal delay for quick tasks. Remove on settlement; retain errors as readable text. Cancel is shown only for supported operations.
  • Scope: animate the smallest affected region; do not blanket-disable the workspace. Pause off-screen and background animations.
Accessibility + recovery handoff

Motion is optional

  • Reduce Motion stops pulses and travel; keep static dots, real counts and accessible status. Review “Pause motion” simulates this visually.
  • Keep a localized, screen-reader-only status for preview loaders. Saving, recovery and settings retain visible labels because the distinction matters.
  • Use polite announcements when a task starts or settles; do not announce every frame, keystroke, tile or checkpoint.
  • Preserve focus and reading position. Review controls use fill and underlined text for keyboard focus, with no blue rectangles.
  • Never replace an error, recovery choice or permission request with perpetual motion. Offer existing retry/reselect actions on failure.
  • Only the submitting action becomes busy for save or cleanup. Hide duplicate animation when the same task already has a primary indicator.
