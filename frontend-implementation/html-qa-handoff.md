## Implemented frontend and actual contracts

- HTML/HTM tree, explicit file, native entry, recent, restore and filename search routing uses `open_local_view` / `open_local_search_hit`, not Markdown `read_document`. HTML never requests section editing/recovery or receives an Edit action. Existing main-renderer HTML refusal remains.
- `HtmlController` validates native shapes, owns one monotonically increasing serialized request queue per token, correlates generation/revision, rejects disposed replies and immediately revokes on disposal. Pending acquisition is cancelled on close and late acquired tokens are disposed. Duplicate identities release unused tokens.
- `HtmlView` owns the actual native mount, measured logical bounds, readiness, hidden retained tabs, resize/focus invalidation, modal/menu hiding, focus, polling, refresh replacement and disposal. It never receives/inserts authored HTML bytes. Authored CSS is isolated from the shell DOM; native geometry has the blocking viewport mismatch recorded below.
- Native baseline typography comes from Reading preferences; authored CSS/theme/language policy stays native. Preference changes replace the view after capture. Zoom is viewer-local and uses acknowledged locations; no HTML source writes or dirty state.
- Neutral HTML/CSS/local/read-only/JavaScript-off metadata, Document Find/Outline/details/path/Reload/Close, resource issues, specific error copy, deliberate per-file/folder resources and linked-file selection are wired. Resource cancellation does not reload; selection explicitly requires Reload. Remote issues have no network-enable action.
- Find uses native visible-rendered-text inspection; Outline uses native visible headings/authored IDs/generated keys. Successful passage jumps and file visits use the existing bounded shared option-D history. New HTML link destinations/reopened history targets are prepared hidden and accepted after native readiness. Failed/cancelled targets preserve source/cursor/branch. Markdown/image providers remain their own readers; generic targets become metadata-only File details.
- Reload captures location, requests replacement, mounts it, then restores after readiness. Failed replacement acquisition retains the old page. A removed authored heading tries preceding surviving headings from the previous Outline, then acknowledged scroll coordinates with an explicit missing-section notice. Polling detects source/resources changed; individual resource errors retain readable content.
- Session anchors include native HTML zoom/horizontal scroll and the existing heading/offset/vertical scroll. Per-view resource grants intentionally do not persist across restart. Folder contents remain explicitly Markdown-only; HTML filenames use the actual native search-hit contract.

## Concrete dependencies and limitations

1. **Native location capture — generated headings:** `src-tauri/src/html_inspect.js`, `location()` uses `h?.id || null`; it does not return the generated `ig-heading-N` key exposed by Outline. `set_html_location` can consume that key, but capture loses it. Native follow-up: use the same visible-heading index/key in capture, retain signed relative offset, and test ID-less Outline → scroll → refresh/history/restore. Frontend retains coordinates when the provider returns no heading ID.
2. **Exact source-link focus / original href:** the current events provide resolved navigation URL and a location; the provider has no durable focused-link identity, original href/text descriptor or focus-restoration command. Frontend can restore the source document and native surface focus, not the exact initiating authored link after picker cancellation/history. Native follow-up: add a bounded grant-independent opaque focus descriptor to captured location/link intents and an acknowledged restoration operation; expose original href/text only as data. Keep scripts/IPC disabled. Optional secondary-link menu remains unavailable rather than fabricated.
3. **IR-03 external default application:** no prepare/commit/default-handler contract exists. File details shows truthful disabled default-app opening with a reason. It never auto-launches. Native owner must implement the previously authorized deliberate handler/policy contract separately; this is an implementation dependency, not missing approval.
4. Native view/resource/request/text limits and conservative HTML/CSS normalization are as documented by the native owner. Remote resource diagnostics are bounded and do not certify exhaustive compatibility/security. Assets selected for a view are transient across restart. Windows remains unverified.
5. **Native geometry blocks viewport acceptance:** macOS content overlaps the resource notice by approximately titlebar height. Native mount/viewport currently convert Tauri client coordinates against NSWindow.contentView directly. Native owner must convert from the actual main webview client view to the sibling parent with correct scale/flipping/titlebar handling. Exact 1280×820 reproduction, affected methods and acceptance matrix are in the evidence report. No frontend offset was guessed.
6. **Reload replacement readiness:** reload_html_view removes/disposes the old token after replacement acquisition, before the replacement mount reaches ready. Acquisition failure retains content, but a later replacement rendering failure cannot retain the old native page through this contract. Native follow-up: stage replacement through ready and commit/dispose explicitly, or expose an equivalent atomic acknowledged reload. Frontend does not claim post-acquisition render-failure retention.
7. **Parent links above virtual grant root:** code inspection shows WKWebView emits only its resolved ig-html URL, and resolve_local_view_link joins its normalized path under the workspace root. A source-root ../outside target can therefore lose its parent context before resolution. Native follow-up: preserve a bounded original link target/opaque intent during normalization and resolve under the source context, then require deliberate access outside grants. Packaged reproduction/result is recorded in the evidence report; no frontend reconstruction from guessed URLs.
8. **Native Find scope:** the inspector walks visible DOM text nodes, so CSS generated pseudo-element content and transformed text are not comprehensively searchable. Native owner must either implement/test the approved rendered-text scope or expose this precise supported limit; frontend does not search raw source or substitute a DOM renderer.
9. **Retained-view return requires final retest:** a pre-final packaged sequence (encoded/missing fragment → dark HTML → Find/Outline → return link) left the source tab active with a blank native body and later unavailable AX. `native-return-hang.sample.txt` records WebKit process-assertion work, not proof of a Rust deadlock or a native-only cause. Final frontend queries actual native window focus within each serialized visible-viewport operation and propagates focus failures. The final candidate repeated encoded/missing fragment → dark HTML → Find/Outline → return link and restored source content/focus/125% zoom successfully once (`frozen-return-source`). This does not establish the cause of the earlier failure; QA must repeat the stress sequence and trace the provider/window if it recurs.
10. Final unresolved regressions, visual mismatches and unavailable manual checks belong in the evidence report; they are not silently accepted here. Initial candidate overlap and interrupted/outdated package attempts are retained as historical failures, not final PASS evidence.
