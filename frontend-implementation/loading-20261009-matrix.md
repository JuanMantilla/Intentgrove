## Integration dependencies / explicit decisions

1. Native picker/grant APIs (`selectFile`, `selectRoot`, session/recent reselection and HTML resource selection) combine UI handoff and verification. Exact “picker dismissed, verification started” timing would require a native phase event/callback with operation identity and terminal result. Current frontend indicates only its actual outstanding promise and never overlays or simulates OS picker controls.
2. HTML reload returns a replacement view token; native mount/dispose/viewport control determines whether the old surface can remain visible. Frontend keeps the current owner while awaiting replacement and uses real ready/failed state. Guaranteed overlap-free old-surface retention would require native support for keeping the old token valid until replacement readiness and explicit atomic activation. No such contract was added; existing native geometry limitations remain.
3. Folder/search scans lack totals. Their tracks are intentionally indeterminate with actual counts. No integration gap is hidden by fabricated progress. Existing supported cancellations remain; save, copy and checkpoint writes have no new Cancel action.
4. E05 Resume uses an already loaded recovery object and performs synchronous state activation. It deliberately has no synthetic loader. Recovery lookup remains with document restoration/acquisition.
5. Proposed 150 ms reveal delay was not added: statuses mount directly from real pending state; motion stays subtle and pauses when hidden. This avoids coupling state settlement to artificial timers. Dots use the approved 1.2 s cycle and 3 px travel, placeholders 1.7 s, indeterminate tracks 2 s.
6. Existing global guards for native file selection/save/cleanup remain because they protect shared native owners. Local feedback does not introduce additional workspace blocking. Background freshness dots are static. Busy action text stays at full opacity where the indicator is attached.
