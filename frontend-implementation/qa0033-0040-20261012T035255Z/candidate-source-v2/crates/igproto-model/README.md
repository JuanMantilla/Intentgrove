# Shared prototype contracts (Phase 1)

This private Rust 2021/MSRV 1.88 library is the canonical V1 machine-readable
behavior definition. Source and compiled scenes share declarations and semantic
validation; actions, transitions, IDs, state and interaction types are reused
unchanged. No VectorCraft, GUI, WebKit, archive, SVG, filesystem, process or network
API is part of the library. The schema-generation example performs developer-only
file writes.

`prototype.source.json` is the editing master. Its required fields are
`sourceVersion:1`, `prototypeId`, `viewport`, `entry`, `visualSources`, `scenes`,
and `interactions`; `title` is optional. Each source scene has `visualBinding`
(source ID, scene-local root target, finite export bounds), role, localState and
optional label. The compiled graph carries `schemaVersion:1`, entry, scenes with
`visual:"scenes/<id>.svg"`, and the same interactions. Viewport/package identity
belong to the source/manifest, not the graph. Visibility state is keyed by a
scene-local TargetId; V1 has no separate StateId or general variables.

Use `decode_source`, `decode_prototype`, and `decode_manifest` for untrusted JSON,
then `validate_source` or `validate_prototype` for model-level checks. Do not call
serde directly on untrusted input: only the shared decoder enforces duplicate-key,
null/control-string, numeric token, byte/depth and early cardinality rules.
Deserialization establishes structure; semantic validation is an explicit step.
Compile-ready source is supported; incomplete draft editing/file revision/atomic
writes belong to later authoring tools.

`serialize_source` emits two spaces, LF, stable field ordering and preserved array
order; it rejects nonfinite bounds before serde can turn them into null. Run
`validate_source` before accepting an authoring edit. Compiler file authority,
actual source digest verification and artboard resolution are separate checks.
The model's relative source path checks grant no filesystem authority.

`validate_source_with_inventory` adds scene-scoped marker/state/root/close-path
checks using `TargetInventory`. Future package/SVG validation must supply complete
inventory facts, including *all* tagged ancestors (nearest first), ordinary-node
kind, sanitation survival and structural display/visibility flags. The ancestor
flags describe authored structure; the close-path check also accounts for explicit
initial state overrides. Clipping, occlusion and actual input reachability require
native QA. The inventory is a trusted typed boundary from a validator, never JSON
supplied as evidence by a package.

`validate(prototype, viewport, inventory)` returns an opaque immutable
`ValidatedPrototype` only after all shared checks pass. This certifies graph and
inventory semantics, **not** archive, resource or SVG safety; Phase 2 must wrap it
in `ValidatedPackage` after admission. `validate_manifest` checks model metadata,
sorted/unique inventory, digest syntax and exact capabilities derived by
`required_capabilities`. File set/path/MIME/hash/length verification and visual
resource facts remain package responsibilities.

Errors carry stable snake_case codes, severity, stage, document-relative member
path, message and optional scene/target/interaction/related identifier. JSON syntax
errors include line/column. Single decode errors are boxed Diagnostics; semantic
checks collect a deterministic ValidationReport, including authoring warnings.
Missing labels/unreachable base scenes warn; unsupported/invalid behavior errors.
Warnings never excuse invalid runtime content.

Source, container and schema versions are independently integer 1; crate semver
is unrelated. Future/older unsupported integer versions fail explicitly, malformed
or missing versions fail, and experimental POC manifests receive a specific error.
Unknown fields/enums and extra action payloads fail. A future consumer must use
these APIs and must not duplicate semantics in TypeScript, MCP or renderer code.

V1 navigation contracts are documented on `Action`: base-only navigation/back,
separate bounded history (32) and modal overlay capacity (1), explicit empty-back
no-op, retained booleans and reset-to-entry initialization. DISSOLVE is exactly
100 ms linear destination fade-in, NAVIGATE only, instant under reduced motion.
This phase implements these data/validation contracts; it implements no reducer,
player, transition acknowledgment protocol or navigation runtime.

The three JSON Schema files are generated by Schemars from Rust types, including
closed enums and constants. They aid editors; references, UTF-8 byte bounds,
viewport area, action contexts and inventory semantics require Rust validation.
