# IR-04 exact frontend handoff

Implemented entry points: `src/main.tsx` mounts `SettingsWindow` for `?settings`; it never mounts `App` in that window. Native workspace General/Reading/Project tree triggers call `settingsApi.show(group)`; the native app-menu Settings/Reading entries use the same window. The browser-only preview retains its existing controls; the native application uses the separate `settings` window. Existing Reading fields/preview are reused. Native titlebar and close remain native.

`src/app/settings-contract.ts` is the consumer contract. All argument keys are camelCase. Errors serialize `{code, message}`. Never pass a window/owner label from the renderer.

- `show_settings({group})`: main only; group is exactly `General | Reading | ProjectTree`. Creates/raises label `settings`, initial 800×720 logical pixels, clamped to the invoking monitor's work area. Body scrolls and Done stays reachable. Repeated group requests increment `activation` so that the target heading is focused/scrolled even when the group repeats.
- `get_settings_state()`: Settings only. Snapshot is `{revision, activation, group, ownerAvailable, values, requestId, persistence, nativeThemeFailed, retryPatch}`. Values are only `{language, appearance, readingFont, readingSize, readingLineHeight, readingWidth, documentsAndImagesOnly}`; no paths, grants, document bytes, drafts, tabs, recents, recovery or search. `persistence` is `saved | failed | pending | ownerUnavailable`. `requestId` and `retryPatch` are nullable.
- `apply_settings_change({requestId, expectedRevision, patch})`: Settings only. ID is 1–64 ASCII letters/digits/underscore/hyphen; UUID fits. A patch has only the value keys above and must contain either General (`language`, `appearance`) or workspace (`reading*`, `documentsAndImagesOnly`) keys. Unknown keys/types, empty/mixed patches, invalid values, stale revision, duplicate recent ID, pending request and unavailable workspace are rejected.
- `acknowledge_settings_change({requestId, revision, persistence})`: `saved | failed` only. General acknowledgment is Settings-only; workspace acknowledgment is main-only. Both ID and reserved revision must match the pending intent. A false disk-success assertion is a renderer bug: acknowledgment means the correct persistence operation actually completed or failed.
- `get_workspace_preferences()` / `publish_workspace_preferences({expectedRevision, values})`: main only, for startup/restore and workspace changes. Publish validates the full preference set, rejects pending/stale writes, advances revision when values or availability change, and synchronizes native themes. This is preference synchronization, not session persistence.
- `close_settings()`: Settings only; follows the normal native close path. It does not call workspace/document close or a final checkpoint.

Value policy: language `en | es`; appearance `system | light | dark`; font `roboto | serif | sans | mono`; finite text size 12–24 px; line height 1.3–2.2. Existing restored Reading widths 320–2000 px remain valid; deliberate new width choices are 480–1200 px. Unchanged legacy widths may accompany another Reading edit. Boolean filter defaults true for old sessions. Serialized patches omit absent keys, rather than sending null resets.

Settings has **zero core/plugin permissions**, including no event listener/emitter. Poll `get_settings_state` (current adapter: every 500 ms while mounted). Apply `newerSettings` to both invoke and polling results: preference revisions and group activation are independently monotonic; a late pending result cannot replace its terminal acknowledgment. Refresh on `settings_stale`; never automatically replay an old patch over newer values. A Retry explicitly uses `retryPatch`, a fresh ID and the latest revision. Pending blocks new changes. Owner loss disables Reading/tree, while General remains usable. Five seconds without acknowledgment advances revision and marks the unavailable owner or unconfirmed General persistence. This is not a claim that an unacknowledged Reading value was never applied.

General writer: Settings uses the existing `md-reader-locale` string and `md-reader-appearance` `{schema:1,mode}` keys, then acknowledges native state. In-memory applied values survive storage failure; Settings supports Retry. The workspace receives the validated General snapshot and updates UI without another incidental write. Existing explicit workspace/macOS appearance menu operations retain their persistence path; queued newer workspace choices win at a subsequent revision. Native theme synchronization covers main and Settings; System follows native/system theme and renderer media changes.

Workspace writer: `useSettingsOwner` listens, in **main only**, for `settings:intent` `{requestId, revision, patch}`. App applies Reading through `applyReadingSettings` (existing anchor capture), or changes only the tree visibility boolean; synchronous refs feed the existing serialized `checkpointSession`. Acknowledgment reports that checkpoint's result. Failure keeps the applied value and draft/tab/tree state. A late acknowledgment rejected after timeout causes the owner to publish its actual current preference state. No session payload goes to Settings.

Focus/lifetime: main retains its connected invoker on `settings:opening`; `settings:closed` restores it, with a Reading trigger fallback. Native focus also returns to main, restoring a minimized owner. Settings drop/close/destroy bypasses workspace close guards and watcher suspension. macOS workspace menu document operations are blocked while Settings owns focus; native Close routes to Settings. App Quit still uses the existing draft guard. Numeric Escape reverts its draft first; a subsequent window-body Escape closes. Done closes; neither writes a final workspace checkpoint.

Frontend follow-through: the functional adapter/body and native App wiring are implemented. Final design/scale/accessibility acceptance remains with frontend/QA: compare the approved 08/16 references, exercise 640×480/enlarged content, physical keyboard/assistive technology, native preference restart and actual edited drafts on both target OSes. Do not replace this window with a popover or expose a general event/file bridge. Windows native mechanism/IPC/close/focus evidence is in `evidence/ir04/windows-webview2.txt`; current macOS build/runtime is NOT TESTED on this Windows host.
