## Ownership and actual implementation

The shared Tauri command host owns grants, descriptors and lifecycle on both platforms. `html.rs`, `html_commands.rs` and `html_broker.rs` own authority and correlation; `html_native.rs` dispatches native main-thread work; `html_surface.m` owns standalone WKWebView; `html_windows.rs` owns standalone Wry/WebView2. `html_inspect.js` is app-controlled inspection, not authored JavaScript. `html_image_budget.rs` performs bounded container/header preflight; engine processes decode images/fonts and lay out HTML. Neither the image XPC nor diagram renderer provides this viewer.

Only the `main` Tauri caller can invoke HTML commands. Settings privileges and main renderer CSP remain unchanged. Document surfaces have no Tauri initialization, IPC handler, host objects or message transport. macOS uses content JavaScript disabled, a fresh process pool, nonpersistent store, app-only defaultClient inspection world, response CSP, compiled resource blocker and navigation/UI delegates. Windows source disables script/web messages/host objects, intercepts all request sources and denies navigation/frame/popup/download/permission/external-URI actions. It requires WebView2 interfaces `_22` and `_18`; interface absence fails mounting rather than weakening isolation.

## Actual API

All arguments use camelCase through Tauri invoke. Complete TypeScript declarations are in `src/app/htmlNative.ts`; they are additive provider adapters, not integrated components. `LocalTarget` is exclusively `{fileId}` or `{rootId,segments}`. `LocalView` is `{fileId,identityKey,diskVersion,name,displayPath,kind,viewToken,generation,bytes,extension}` where kind is `markdown|image|html|details`; only HTML has a view token. `HtmlOwner={viewToken,generation}`; `HtmlRequest` adds numeric `requestId`. New tokens start generation1; replacement always receives a new token.

| Command | Arguments beyond owner | Result / meaning |
|---|---|---|
| `open_local_view` | target, requestId:string, expectedIdentity?:string | LocalView; no mount implied |
| `cancel_html_open` | requestId:string; no owner | boolean pending match; cancellation also tombstones a not-yet-started ID |
| `mount_html_view` | requestId, bounds, visible, baseline? | HtmlState, usually opening; await ready event/state |
| `update_html_viewport` | requestId, bounds, visible | void |
| `get_html_state` | none | HtmlState plus source/resource change detection |
| `capture_html_location` | requestId | snapshot: headings/location/empty |
| `set_html_location` | requestId, location | snapshot with actual location |
| `find_html_text` | requestId, query, backwards | count/current/location; empty query clears selection |
| `focus_html_view` | requestId | void; hidden view fails |
| `reload_html_view` | requestId | replacement LocalView; old token disposed |
| `choose_html_resource` | issueId | HtmlState or null when picker cancelled |
| `choose_html_resource_folder` | none | HtmlState or null |
| `resolve_local_view_link` | navigationId | HtmlLink; consumes native intent once |
| `choose_html_link_file` | accessId | `{view:LocalView,anchor:string|null}` or null |
| `dispose_html_view` | none | boolean; idempotent for absent token |
| `open_local_search_hit` | jobId, hitId; no owner | validated LocalView for active search generation |

`HtmlState={viewToken,generation,revision,requestId,state,reasonCode,issues,headings,location}`. State is `opening|ready|empty|failed`. Each heading is `{key,authoredId,level,text}`. Each issue is `{id,declaredUrl,kind,reason}`. Location is `{headingId,offset,scrollTop,scrollLeft,zoom}`. Events to the main window: `html:view_state` and `html:location_changed` carry HtmlState; `html:link_activated` carries owner/revision/navigationId/destination/last captured location; `html:shortcut` carries owner/key/shift; `html:viewport_invalidated` requests fresh layout after main resize/focus loss. Location events occur on requested operations, not every scroll tick. Capture before leaving a page; the last state location alone may be stale.

Use unique opening request strings (1–64 bytes); use strictly increasing safe-integer numeric request IDs per mounted token. Reject replies/events for inactive tokens/generations and older revisions. Serialize mount/inspection/location operations: a newer inspection intentionally supersedes an older pending reply. Open cancellation checks before and after bounded reading; dispose any success received after frontend cancellation. Tombstones are bounded to256, pending opens16, views16. Do not reuse request strings. Readiness is correlated to the mounted owner, independently of viewport request supersession; startup resize cannot consume the ready reply. Ordinary inspection replies still reject stale requests. Resource reads run off the Cocoa/STA thread under a serialized broker gate; disposal immediately revokes ownership while queued/running reads finish cooperatively and cannot deliver to disposed surfaces. Native request admissions are capped at129 including the source; Windows queued worker/completion jobs are separately capped at128. Source grants remain in the shared AppState; closing a viewer revokes its assets and rendering token, not an independently retained source grant. Session/history commits belong to the frontend after accepted success, never on an unaccepted link or cancelled selection.

## Grants, resources and security

HTML source is UTF-8 and at most4MiB. Every broker request validates source grant/current identity and stamp; resources use no-follow handles with identity/stamp checks before and after read. A workspace root grant authorizes descendants; an explicit file grants only that file. Its volume-root-relative URL preserves ancestry for authored ../ paths; that naming root and every ancestor are never authority. Root-granted views retain workspace-relative virtual URLs. A reference escaping a workspace virtual root stays unsupported; cross-volume/file-URL resource references are blocked. A resource-file selection retains only that exact requested path/identity. A separate resource-folder selection grants descendants for that view without replacing the workspace root. Picker cancellation returns null; selection does not silently reload. Close/reload invalidates ownership and late picker responses are checked again.

Supported resources: authored inline/external CSS, bounded nested static imports, PNG/JPEG/GIF/WebP and WOFF/WOFF2/TTF/OTF signatures. Budgets per load:128 requests,64MiB reserved total including failed reads and one growth-guard byte per filesystem read; CSS1MiB/file and4MiB total including rejected assets,128 import declarations across all stylesheets (remote declarations included), import depth8/cycles rejected; fonts8MiB total including rejected font data; images16MiB compressed/file,32MP/frame,100frames and128MiB estimated decoded aggregate. Resource admission/load deadline5s from descriptor creation; blocking OS reads cancel cooperatively, operation reply deadline6s. Sixteen live views,32 per-view asset selections,128 diagnostics with2048-character display URLs (full URLs retained privately by issue ID),4096-byte broker URLs;1000 headings/2048-character text; Find256-byte query,2Mi UTF-16 text,100000 text nodes,10000 matches. Limits fail visibly. CSS escapes/unrecognized import syntax are conservatively unsupported. Dynamic late/lazy resources after the deadline are denied. Header budgets are not a hard OS memory limit.

Remote/file/absolute resource loading is denied. No document-triggered external-app launch exists. CSP/native policy deny script, event-handler execution, network connections, forms, frames/object/embed, downloads, popups, redirects and automatic navigation. File/submit controls are disabled before showing readiness. External SVG is not served; inline SVG presentation remains under script-off/CSP. Remote diagnostics are bounded and not an exhaustive enumeration of every CSP refusal. Disposal stops loading, revokes broker state/assets and releases views/delegates/observers/timers; the engine owns subprocess termination.

## Mounting and interaction

Bounds are logical client coordinates `{x,y,width,height}`, finite, positive and entirely within the main client area. Native child content sits above shell DOM: hide it **before** any shell modal, menu overlay, tab switch, Settings transition or blocking picker. Reposition/hide with `update_html_viewport`; never let it cover the tab strip/sidebar. Surfaces start hidden and become visible only after inspection readiness. Resize/focus loss hides all native surfaces; on invalidation/focus return measure the approved reading region and send fresh bounds/visibility. Explicit focus targets the surface; hidden focus returns `hidden_view`. Disposal is required on tab close and replacing owners; application shutdown also disposes all.

Cmd/Ctrl+F/R/W/O are forwarded via shortcut events (including shift) to the existing shell dispatcher. No new navigation shortcuts were added. Preserve option-D navigation-arrow placement at the beginning of the tab strip; do not redesign shell navigation. Authored light/dark CSS is preserved and not theme-inverted. Baseline defaults to bundled Roboto16px/1.6. Supply optional mount baseline `{font:roboto|serif|sans|mono,size:12..24,lineHeight:1.3..2.2}` from current Reading preferences. Fallback CSS is injected only when no authored styling is detected (style elements/attributes or stylesheet links); authored documents retain normal browser canvas and inheritance semantics. Detection is conservative, so style-like text can suppress the fallback. Roboto/Roboto Mono are broker-served compiled app assets charged against font/request budgets, independent of document filesystem grants. Remount/reload to apply changed baseline; viewer zoom remains separate. HTML gets no editing/source controls.

Find searches visible text across inline text nodes, case-insensitively, returns1-based current match and count, selects/scrolls the match, and excludes hidden/script/style content. Outline includes visible h1–h6; authored IDs are preserved and generated keys refer to visible heading indexes. It does not mutate authored IDs. Location restores an authored ID/generated heading plus signed offset, otherwise signed horizontal and nonnegative vertical scroll coordinates; zoom is applied before resolving a heading, so anchor_missing may still apply the requested zoom. For fragment-only operations pass current viewer zoom. Missing heading returns `anchor_missing` without guessing. Fragments decode once; empty fragment means document start. Zoom0.5–3 is native viewer-local magnification, independent of Markdown typography/global zoom.

## Routing, refresh and restore

Native acquisition now recognizes case-insensitive .html/.htm in pickers, folder/native entries, recents and restore. Search scans HTML filenames only; contents are never indexed. Native document events retain the existing document event shape: the receiver must inspect classification/name and call open_local_view rather than Markdown read_document. HTML cannot enter editing/recovery journals.

Only native-captured deliberate link intents can be resolved. Same-document fragment → location; local HTML → granted fileId, then open_local_view({fileId}, fresh opening request); Markdown → existing reader; image → existing image provider; other files → IR-03 File details. `HtmlLink.kind` includes anchor/html/document/image/details/blocked/unsupported/missing/access_required. No external application launches. File-only sibling/ancestor links return `access_required` with requestedPath/accessId: offer deliberate selection and call choose_html_link_file; exact-path mismatch fails, cancel retains current document. Query-bearing local links are unsupported. Native routing validates source grants again. Frontend decides new/current tab and history using the approved handoff.

Refresh is capture → reload_html_view → mount replacement → await ready → set_html_location. Failure to create replacement retains the old readable view; mounting failure occurs after old descriptor disposal. Reload preserves asset selections and revalidates them, never silently expands grants. At the16-view cap replacement allocation can return html_limit; close another inactive view before retry. Existing stable125ms refresh fingerprinting supports HTML; confirmed Markdown text APIs remain Markdown-only. Poll get_html_state while active: reasonCode changed/resources_changed means offer/reload through HTML. No independent resource-folder watcher is implemented.

Session schema1 adds optional htmlZoom/htmlScrollLeft to existing reading anchors and reports kind. Persist/capture location before checkpoint, restore grants through existing session path, open/mount through this provider and restore location only after readiness. Separate resource selections are intentionally transient and must be selected again after application restart. Explicit source identity replacement requires reselection; root-granted replacement follows the existing granted refresh path.

## Errors and receiving work

Relevant codes include invalid_request/invalid_target/invalid_viewport/invalid_location, html_denied/html_limit/html_render_failed, stale_view/stale_request/stale_navigation, cancelled, reselection_required, changed, missing/denied/outside_grant, invalid_resource/resource_mismatch and anchor_missing. Resource issues do not turn a readable page into whole-document failure. Render failure, invalid UTF-8/source budget or unavailable platform engine is a document failure. Native error message text is diagnostic, not localized user copy.
