## Final source behavior

The final broker reserves file length plus a bounded growth-guard byte before I/O; rejected resources consume the aggregate and applicable CSS/font budgets. CSS import declarations are capped globally before URL graph allocation. Diagnostics retain exact broker URLs privately by issue ID while displaying bounded labels. Source read failure preserves its specific broker reason code. Broker I/O runs off the native UI thread without holding ownership locks, so disposal revokes pending reads immediately; blocking OS reads finish cooperatively. macOS scheme tasks and Windows deferrals reject delivery after disposal. Search-hit and refresh opening recheck ownership after blocking acquisition and discard stale replacement descriptors.

Readiness belongs to the current mounted token/generation rather than an incidental viewport request. The native harness deliberately changes the native and backend request during pending readiness; every final document must still become ready/empty. Ordinary inspection replies remain request-correlated. Authored light/dark canvas is retained; a screenshot corner-pixel assertion detects the previous white-gutter fallback defect. The fallback reading baseline applies only to conservatively detected unstyled HTML. Explicit-file URL ancestry supports parent-relative references without granting any ancestor; parent resources require deliberately retained selected handles.

Historical attempts are retained: earlier candidates predate the final authored-canvas, ancestry, async-delivery, readiness and budget changes. They are not the final identity. The shell-default Node20 frontend run stalled with two workspace-handoff failures; the full explicit Node24.20.0 run passed383 tests in55 files. No assertion or timeout was relaxed; the earlier cause was not established. Native tests do not prove WebKit isolation, and mocked frontend tests do not prove Tauri transport.
