## Cause and traced flow

Terminal Cmd+click delegates file opening to macOS; Intentgrove receives the same `RunEvent::Opened` file URLs as Finder (`lib.rs:805`). Drops enter the native queue at `lib.rs:779`. The automatic file-only consumer in App calls `accept_native_entry`, which uses `register_explicit_file`; picker opening also registers individual-file handles. Neither creates folder access. Native entry/restoration ordering remains intact.

Markdown links reach App `navigate` (`App.tsx:2651`) then `assets::resolve_link`. Previously `target_from` rejected every non-root source, and frontend error handling replaced its result with the folder-reopening message. HTML used a separate deliberate-link broker that unconditionally requested file selection for individual sources. Both were application policy restrictions. Current `tauri.conf.json` and main-app packaging configure no App Sandbox entitlement. Existing OS read/permission/local-only/no-follow checks remain authoritative. Apple's [App Sandbox guidance](https://developer.apple.com/documentation/security/accessing-files-from-the-macos-app-sandbox) describes a separate entitlement/security-scoped-access boundary; this patch changes no sandbox or entitlements. An attempted inspection of the previously documented release bundle found that bundle absent, so actual installed-package entitlements were not verified.

## Change and security boundary

Relative links use the individual source's parent directory, decoding each path segment and fragment separately. Source identity is checked against its current path. A temporary common-parent handle and existing `open_relative` walker enforce no-follow target components and local regular-file checks. Only the resulting already-open target handle is registered as an individual file; no workspace root, directory grant, unrestricted filesystem capability, dependency or arbitrary path-opening IPC is added. Target handles avoid reopening between validation and registration. Existing explicit-grant identity deduplication, restore and editing ownership are reused.

Supported Markdown/HTML/image targets reuse existing frontend openers with individual-file metadata. Same-document targets return anchors; repeat visits and existing dirty tabs retain their owners and content. Missing/access/unsupported native errors are shown accurately instead of telling users to reopen through a tree. HTML shares the same deliberate-target helper; actual denials retain the existing exact-file picker and fragment continuation. Picker cancellation retains source, mismatched selection remains refused. Live picker approval/TCC behavior is not claimed as tested. Automatic embedded image/HTML-resource access remains separately scoped. Existing folder-link containment and external-link routing are retained.
