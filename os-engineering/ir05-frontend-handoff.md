# IR-05 exact frontend integration handoff

Native contracts are implemented. `src/app/api.ts` exposes them. `App.tsx` already publishes Go state from committed history and consumes the four actions using existing traversal/dialog/clear functions. There is no second native history. No shortcuts were added. macOS native menu clicks still need host acceptance; Windows continues using the existing client Go menu.

## Menu contract

Call `setNativeMenuState` with the existing state plus `back`, `forward`, `visited`, `clearHistory`. All four are optional for older callers, default disabled natively. `back` matches the previous committed entry, or the current retained entry when all tabs are closed. `forward` requires an active document and next entry. `visited` and `clearHistory` require entries. All are false during history traversal, matching the current client menu. Publish after committed history/active tab/guard changes; failed or pending document loads never become visits.

Listen on existing `native:menu` for `go_back`, `go_forward`, `go_visited`, `go_clear`. Recheck current guards when processing an event; use `traverseHistory`, set history direction null/open the existing Visited dialog, and `clearVisitHistory`. Clear retains the current committed visit and leaves documents/tabs open. Settings focus suppresses native Go dispatch. Events target `main`, not all webviews. EN/ES native labels are supported.

## Search contract and remaining panel work

`api.startFolderSearch(rootId, query, mode, includeIgnored, scopeSegments?)` invokes `start_folder_search`. Mode remains `name | content | both`. Omitted/null/empty scope means root. A nonempty scope is an array of literal directory components relative to the existing grant, e.g. `["notes", "research"]`. Do not send display paths, joined strings, `.`/`..`, drive paths or separators within components. Native validation is authoritative and rejects links/reparse points even when their target is internal.

Acknowledgment is `{jobId: string, generation: number, scopeSegments: string[]}`. `scopeSegments` is the native-confirmed root-relative scope; display that separately from search mode. Result `segments` and `path` remain root-relative, preserving existing tree/tab requests. `folder-search:batch`, cancel and opaque `openSearchHit(jobId, resultId)` contracts are unchanged. Never implement result open by directly reading a displayed path. Jobs/results are in-memory and are not session grants.

Remaining frontend work is in `FolderSearchPanel.tsx` and the folder context action in `App.tsx`: carry selected folder segments into the panel; enable the currently disabled narrower action; retain the explicit scope independently of query/mode; pass it as the fifth argument; accept/display the acknowledgment; invalidate current/pending search and open sequences on scope changes even when root ID/generation are unchanged. Keep pending-start cancellation, bounded early batches, replacement-job sequencing, and stale-open checks. The listener currently captures a root and uses refs; scope must have the same current-owner treatment. Until this wiring is completed, the existing UI continues root search.

On `scope_changed`, show a localized explanation that the searched folder changed and offer a fresh search/reselection; discard that job's displayed hits. For `invalid_grant` or `root_reselection_required`, retain existing expired-root recovery. Other validation/access errors retain `invalid_path`, `missing`, `denied`, `unsupported_type`, `unsupported_mount` or native adapter codes. Invalid start requests do not replace/cancel the prior valid native job. `partial` is not completion. Stop keeps collected hits openable; a replaced job refuses its old hits with `invalid_grant`. Clear cancels both current and pending work, clears results, retains the scope and panel, and changes no grants. Return to Explorer keeps tree expansion/scroll state.

Native checks cover nested ignores, ancestor pruning/whitelists, includeIgnored, root compatibility, traversal, internal/external junctions, forged sibling hits, root and scope replacement, Stop and late cancellation. Frontend integration must additionally test pending scope switches, buffered batches arriving before acknowledgment, old cancellation/open replies, Scope/Both independence, Clear/Return, EN/ES focus and scope error recovery. Run actual macOS Go/menu/Settings-focus and Windows/macOS search journeys with disposable folders. Existing packaged 25k cancellation and release acceptance tasks remain open.
