## Implemented slices

- **FR-011:** narrow macOS filesystem/enumeration, private-storage/locking and stage/commit mechanisms extracted into `src-tauri/src/platform/`. Shared grants, errors, section composition, bounded read/search/refresh policies, record envelopes and Mac version-token format retained. Direct-source Rust integration tests include the adapter module.
- **FR-001–004:** Windows source prototype uses metadata/no-recall checks, NT handle-relative child opens with OBJ_DONT_REPARSE, local disk/NTFS checks, 64-bit volume/file identity with refusal of unrepresentable high file-ID bits, bounded handle enumeration and explicit-offset reads. Only the drive root uses CreateFileW; this avoids treating the DOS drive's object-manager alias as a filesystem descendant. All filesystem components below it use held parent handles. Native rename/reparse/recall/race proof remains outstanding.
- **FR-006:** framework local app-data directory on Windows; protected current-user directory DACLs and owner checks; unsafe existing DACLs are rejected. File creation, private publication and removal use owned handles. Windows locks deny deletion sharing, serialize transient contention with a two-second bound, and explicitly unlock on drop. Recovery/recents/session/safety-copy schemas remain unchanged. Previous valid checkpoints are copied and flushed before publication on Windows; Mac hard-link behavior remains. Post-publication verification errors disclose uncertainty. Windows directory checks do **not** claim Unix directory-fsync or power-loss durability.
- **FR-005/010:** original Save/Save As, edit-session creation and recovered edit-session restoration are denied natively on Windows. UI disables editing and suppresses Save shortcuts. No Windows original-document commit API is enabled or represented as verified. Mac staged saves remain implemented. Windows decoding returns image_unavailable; XPC linkage is Mac-only. No raw-image/webview fallback was added.
- **FR-002/008:** Ctrl commands, Ctrl hints, EN/ES device wording, read-only explanation and Windows display-path breadcrumbs reuse the current interface. Dialog/drop pending-selection flows remain shared. Confirmed Windows close stops refresh and requests final process exit. The expected bundled `http://tauri.localhost` origin is target-scoped in navigation policy; CSP/capability configuration is unchanged. Actual WebView2 origin, navigation restrictions and shutdown must be checked natively.
- **FR-009:** `src-tauri/tauri.windows.conf.json` prepares NSIS/currentUser, no file associations, no automatic WebView2 installation and no signing settings. Configuration JSON, property names and enums were checked against the installed Tauri schema. Installer construction is gated on native verification and already available bundler tools; none was attempted.

Tests added: `tests/ui/windows-platform.test.tsx` exercises actual App with mocked Tauri, Windows modifiers/disabled edits/localized copy and display paths; `platform/windows_path.rs` tests pure Windows path rejection on Mac. `src-tauri/tests/windows_scoped.rs` contains native Windows fixtures for Unicode/BOM/CRLF bounded unchanged reads, cancellation, held-root rename/replacement, streams/reserved names, synthetic offline attributes, junction escape prevention, lock release and private publication. These native fixtures are **NOT TESTED**. Unix-only permission/symlink/save fixtures are target-scoped; shared parser/envelope/reader tests remain available on Windows. Native Windows denied-DACL, actual cloud-provider, multi-process contention, crash/restart and safe-save cases still need additional experiments/coverage.
